# tools/ —— 只剩一个可选件

插件本身**不需要这里的任何东西**。整条链路（搜索、字幕、评论、抽帧、转写、扫码登录、ffmpeg）都已在插件里用 Node 实现，装完就能用。

这里留下两样东西，都是给愿意折腾的人准备的：

## 1. `parse_svc.py` —— 自建解析服务器

把一台服务器变成你自己的取流来源。插件里的「只走自己的服务器」模式会用它。

```bash
python3 parse_svc.py --port 8848 --gap 1.5
```

| 接口 | 返回 |
|---|---|
| `GET /health` | 存活、调用次数、风控次数 |
| `GET /playurl?bvid=BVxxx&cid=123` | 音频轨与视频轨直链（3 音频 + 4 视频） |
| `GET /subtitle?bvid=BVxxx&cid=123` | 字幕轨（需要 cookie） |

有什么用：把取流请求放在服务器 IP 上，本机不消耗 B 站配额。实测同一 IP 连续约 30 次请求开始 412，所以多一台机器就多一份配额。

配好之后在插件里填地址（面板「取数方式」选「走自己的服务器」，或在对话里说 `/bili endpoint http://你的地址:8848`）。

## 2. `sources.md` —— 第三方解析站的实测清单

13 个站的真实数据：打开速度、能不能吐直链、为什么不能。写这些是为了**不用重复踩坑**。

结论一句话：它们在纯 HTTP 请求下都不给直链，但用浏览器点一下可以（见 `plugin/docs/BROWSER_SCRAPE.md`）。
