# dsh-bili-learn

> 让 AI 真正"看"B 站。字幕、评论、画面、口播——一次性变成 AI 能逐字读的文本。

一个 DeepSeek Harness 插件。装完即用，**不需要 Python，不需要 ffmpeg，不需要开开发者工具**。

---

## 问题：知识在视频里，AI 读不到

你用 AI 学东西，几乎一定卡在同一处。

| 你想让 AI 知道的 | 实际情况 |
|---|---|
| UP 主讲了什么 | 干货在**字幕**里，但**只有约 11% 的视频有字幕** |
| 屏幕上的代码、PPT、界面 | 字幕里一个字都没有 |
| 观众怎么评价 | 评论区接口**只给 3 条预览**，除非登录 |
| 没有字幕的视频 | 口播内容彻底丢失，AI 无从下手 |

结果只能你自己看完、再复述给 AI。慢，而且会漏。

## 它做的事

一句话：**把一条 B 站视频，变成 AI 能逐字读的文本，然后交给它干活。**

```
你说：「学习B站上前端的做法，帮我做一个前端」
   ↓
它去找高播放视频 → 抓字幕/评论/画面 → 落成本地 markdown
   ↓
派几个子 agent 并行读 → 合并成一份笔记 → 开始动手
```

四条数据通道，各自补一块：

| 通道 | 拿到什么 | 需要登录吗 |
|---|---|---|
| 字幕 | UP 讲的原话，带时间轴 | 需要（扫码一次） |
| 语音转写 | 没字幕时的口播全文 | **不需要** |
| 画面 | 抽帧 + 视觉模型，读出屏幕上的文字与界面 | **不需要** |
| 评论 | 高赞评论，登录后可翻页 | 看深度 |

## 30 秒开始

```bash
git clone https://github.com/admiremaozhuxi/dsh-bili-learn.git
```

1. DSH → **Plugins → Add plugin** → 选 `plugin/` 目录
2. 左侧栏出现「B站视频小工具」→ 打开 → 点**扫码登录**（手机扫一下，不用输密码）
3. 直接说：「学习B站上×××，帮我做×××」

首次「看画面」时插件会自己下载一个 ffmpeg（约 28 MB，国内镜像约 5 秒），之后不再下。

**这些都不用你做**：装 Python、装依赖、复制脚本到某个目录、F12 抄 cookie。全部没有。

## 为什么不用现成方案

| 方案 | 差在哪 |
|---|---|
| `yt-dlp` 下载视频 | 给你一个几百 MB 的文件，AI 读不了；也没有字幕提取和评论 |
| 在线解析站 | 只给视频直链，不给字幕；而且要人工过验证码 |
| 浏览器字幕扩展 | 能取字幕，但要你在每个视频页手动点一下，无法批量 |
| 直接爬接口 | 这正是本项目的活：处理 WBI 签名、风控退避、字幕缺失、画面理解 |

本项目的差异在于**它面对的是"读完之后要干活"**，不是"保存一个文件"。

## 实测结论（2026-11，真实接口）

这部分是项目的价值所在——网上流传的说法有几条是错的。

| 结论 | 证据 |
|---|---|
| **元数据不要逐条查** | `ranking/v2` 一次返回 100 条，自带 `bvid / cid / aid / title / desc / duration / owner / stat`。实测 3 次调用拿到 292 条 |
| **`view` 接口无 cookie 会 -412** | 返回 HTTP 412 / `{"code":-412}`。所以本项目**全程不用 `view`**：`search/type` 自带 `aid`，`player/pagelist` 自带 `cid` |
| **字幕必须登录** | `player/v2` 无 cookie 实测 **0/16**；签名版 `player/wbi/v2` 也是 **0/3**，且 `allow_submit=false`。不是接口选错，不是签名算错 |
| **字幕覆盖率约 11%** | 4 个分区 9 条视频，只有 1 条带字幕轨（`ai-zh`+`ai-en`，拉到 792 行）。知识类高，游戏舞蹈基本没有 |
| **评论无 cookie 会截断** | 未登录时请求 `ps=20`，实际只回 **3 条**预览。**登录后每页 20 条**，可翻页（`pn`），可取二级评论（`/x/v2/reply/reply`）。实测翻两页拿到 40 条，二级评论 6 条 |
| **`wbi/view` 登录后可用** | 无 cookie 时 `view` 返回 412，一度以为它永久不可用。实测**登录后 `wbi/view` 正常返回**，能拿 `aid`（评论接口必需，`pagelist` 不给） |
| **分P 必须单独处理** | 网课往往几十上百个 P。实测黑马程序员 Python 教程 **536 个 P、总时长 55 小时**。只取第一个 P 等于什么都没读到，所以 `bili_series` 先列清单、`bili_watch` 用 `p` 指定哪一集 |
| **单P 弹幕数拿不到** | `x/v2/dm/web/view` 返回 protobuf/XML（非 JSON），`x/player/dm` 直接 404。改用「标题 + 时长 + 首帧图」判断重点章节，整片弹幕总数从 `view` 的 `stat` 拿 |
| **UP 粉丝数要另调接口** | `view` 只给名字不给粉丝数；`x/relation/stat?vmid=` 可用。实测黑马程序员 506 万粉 |
| **直链不需要 cookie** | `/x/player/wbi/playurl` 返回 `code=0, dash=true`。实测下载 3 MB/s |
| **一次请求带 3 个候选地址** | 主地址 + 2 个备用 CDN，天然冗余，不需要第三方 |
| **风控计数单位是 IP** | 同一 IP 连续约 30 次请求开始 412。「开 8 个 agent 并行」= 8 倍速送进冷却 |

最后一条决定了架构：**取数串行限速，阅读并行 fan-out**。

## 七个工具

| 工具 | 用途 |
|---|---|
| `bili_learn` | 按主题批量采集：搜索 → 按播放量排序 → 抓字幕/评论 → 落盘 |
| `bili_study` | **一键全流程**：采集 + 派子 agent 并行研读 + 合并简报 |
| `bili_watch` | 单条 BV 号深度抓取，不用搜索。多集课程可指定第几集（`p`）；评论可翻页、可取二级评论 |
| `bili_series` | **看整个系列**：网课/系列课的全部分P清单、UP 主资料、整片统计，可探测哪几集有字幕 |
| `bili_frames` | **看画面**：抽帧 + 视觉模型，读 PPT、屏幕代码、界面状态 |
| `bili_transcribe` | **声音转文字**：没字幕时把口播转成文字，不用登录 |
| `bili_sources` | **查来源**：现在哪些来源能用、多快，用于决定采集计划 |
| `bili_config` | 读写取数方式、阅读编排、自建服务器、登录凭证 |

面板里也能直接改设置（取数方式、并发、自己的服务器、第三方站开关），点保存立即生效。

## 子 agent 怎么分配

学一个主题只看一个视频容易片面。所以同时读几个不同来源，每个视频再分几个 AI 去读。

| 设置 | 含义 | 默认 |
|---|---|---|
| **同时阅读视频数** | 一次看几个不同来源 | 3 |
| **每个视频分配 AI** | 区间，内容越长给越多 | 2–4 |
| **AI 总数上限** | 同时在跑的硬上限 | 12 |

### 关键机制：短片读完后，它的 AI 转去帮长片

举个例子：3 个视频，池子上限 6。

```
短视频 A（2 段） → 用 2 个 AI
短视频 B（2 段） → 用 2 个 AI
超长课 C（8 段） → 用了 8 个 AI   ← 超过「每片 2-4」的上限

worker1: A#1 → C#3    ← A 那两份读完后，这个 worker 转头读 C 剩下的段落
worker2: A#2 → C#4
worker3: B#1 → C#5
worker4: B#2 → C#6
worker5: C#1 → C#7
worker6: C#2 → C#8
```

所以有两条保证：

- **单个视频实际动用的 AI 可以超过「每个视频分配」的上限** —— 靠别处空出来的 worker 补上
- **但同时在跑的总数永远不会超过「AI 总数上限」**

实现上就是「所有段落进一个队列 + 固定大小的 worker 池」。短片的任务少，做完自然去队列里领长片剩下的段，不需要额外的调度逻辑。

三个数值面板里都能直接调，也能用命令改：

```
/bili videos 3          # 同时读几个视频
/bili agents 2-4        # 每个视频分配几个 AI（区间）
/bili total 12          # AI 总数上限
```

> **注意**：这里限制的是「同时跑几个子 agent」，和取数限速是两回事。取数始终串行并带 `gapMs` 间隔，因为 B 站风控的计数单位是 IP 请求数，不是 agent 数量。加 agent 不会加快取数，只会加快**读取和提炼**。

## 取数方式

| 模式 | 行为 |
|---|---|
| `auto` | **推荐**。先试自己的服务器；不通就两条直连并行，谁先成功用谁 |
| `direct` | 只走官方接口，两条并行 |
| `self` | 只走自己的服务器，本机不出网 |
| `proxy` | 第三方网页站（需人工点验证码，作兜底） |
| `default` | 不取视频文件；搜索、字幕、评论照常 |

### 有服务器的话

把 `tools/parse_svc.py` 跑起来，面板里填地址，取流请求就走服务器 IP，本机不消耗配额。

这不是必须的——但如果你有机器，这是唯一能真正放大配额的方式，因为**风控的计数单位是 IP，不是线程数**。

## 关于字幕

**字幕需要登录态。** 实测无 cookie 时 `player/wbi/v2` 返回 `code=0` 但字幕数组为空，连 `ai_status` 字段都不返回。

登录后能拿到，但**覆盖率只有约 11%**。所以真实策略是两条腿：有字幕直接取（快），没字幕就走音频转写（慢但一定有）。

登录方式：面板点「扫码登录」，手机 B 站 App 扫一下。凭据存在本地，不动别处。

---

## 已知限制

- **画面**：走最低码率（640×360），够读文字和界面，不适合收藏
- **转写**：耗时约等于音频时长，适合几条关键视频，不适合批量
- **风控**：同一 IP 约 30 次请求触发 412，冷却后恢复
- **内网代理**：第三方站的直链要人工过验证码，无法自动竞速（实测 13 个站，纯 HTTP 请求全部不给直链）
