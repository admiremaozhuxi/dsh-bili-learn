# B站学习器

把 Bilibili 当作一个**研究资料库**而不是视频站：按播放量搜索 → 抓字幕与高赞评论 → 写成本地 markdown → 交给子 agent 学习 → 再动手施工。

## 它解决什么问题

普通搜索给你链接和标题，B 站的视频正文藏在**字幕**里。这个插件把正文取出来、落成本地文件，让 agent 能真正「读完再干活」。

典型对话：

> 学习B站上前端的做法，帮我去做一个前端

DSH 会调用 `bili_learn`，按播放量抓一批高相关视频，写成 markdown，然后读取这些文件再动手。

## 五个工具

| 工具 | 用途 |
|---|---|
| `bili_learn` | 按主题批量采集：搜索 → 排序 → 抓字幕/评论 → 落盘 → 返回索引 |
| `bili_study` | **一键全流程**：采集 + 派子 agent 并行研读 + 合并成一份 brief |
| `bili_watch` | 单条 BV 号深度抓取，不用搜索。多集课程可指定第几集（`p`）；评论可翻页（`commentPages`）、可取二级评论（`replyLimit`） |
| `bili_series` | **看整个系列**：分P清单、UP 主资料（含粉丝数）、整片统计，可探测前几集是否有字幕 |
| `bili_frames` | **看画面**：抽帧 + 视觉模型，读 PPT、屏幕代码、界面状态、操作演示 |
| `bili_sources` | **查来源**：现在哪些来源能用、多快，用于决定采集计划 |
| `bili_config` | 读写取数方式、并行度、自建服务器、登录凭证 |

## 来源与风险分摊

有三类来源，失败方式各不相同：

| 类 | 是什么 | 能自动用吗 |
|---|---|---|
| `api` | 官方两条接口路径 | ✅ 自动竞速 |
| `self` | 自建解析服务器 | ✅ 自动竞速，且把风控挪到服务器 IP |
| `web` | vtool / v2ob / iiilab 等网页解析站 | ❌ 要人点验证码；**但每个站点有自己的出口 IP** |

**网页站的价值不是 API，是出口 IP。** 实测它们在纯 HTTP 请求下一个直链都不给，可是让子 agent 用浏览器去点，就能借用它们服务器的 IP —— 这对**没有自建服务器**的用户是唯一的分摊手段。

### 怎么用

```
bili_sources({ refresh: true })     # 先看谁在线
```
返回里会直接给建议：接口类可用就正常采集；接口类全挂就派子 agent 走某个在线网页站。

大采集时按并发派子 agent，**每个子 agent 指定不同的来源**，比全部挤在一条路上更不容易被拦。

### 启动自检

插件激活 6 秒后自动探测一遍所有来源，结果缓存在 `~/.dsh-bili-learn/sources.json`，面板「说明」页直接显示每个来源的在线状态与延迟。超过 10 分钟视为过期，可以点「重新检测」。

## 面板与命令

左侧栏的「B站学习器」面板是可操作的，不是说明书：

- **配置页**：点选取数方式、用 − / + 调并发与请求间隔，底部实时生成一行 `/bili set ...` 命令，一键复制
- **工具页**：五个工具一览，每个都能点「复制名」
- **状态页**：数据能力对照表、产物位置、命令速查（每条可点复制）

为什么面板生成命令而不是直接改配置：Client 插件没有 Host 文件的写权限，DSH 认可的方式是「UI 生成命令 → Host 命令处理器执行」。所以同一套逻辑有三个调用者 —— 面板按钮、`/bili` 命令、`bili_config` 工具，共用 `saveSettings`。

### 命令

| 命令 | 作用 |
|---|---|
| `/bili status` | 查看当前配置 |
| `/bili mode auto` | 切换取数方式 |
| `/bili concurrency 6` | 调整并发（1–12） |
| `/bili gap 1500` | 请求间隔（300–5000ms） |
| `/bili endpoint URL` | 自建服务器地址 |
| `/bili cookie SESSDATA=...` | 写入登录凭证 |
| `/bili clearcookie` | 清除登录凭证 |
| `/bili test` | 测试自建服务与登录态 |
| `/bili set mode=auto concurrency=6 gap=1200` | 一次提交多项（面板用的就是这条） |
| `/bili reset` | 恢复默认 |

`bili_study` 是给「学习完就动手」准备的：它把采集和研读一次做完，不用多轮往返。
派发失败时不会报错，而是降级返回文件列表和明确指令，所以任何情况下都不会空手而归。

采集产物：

```
~/.dsh-bili-learn/harvests/<时间>-<主题>/
  index.json      索引：标题 / 播放量 / 字幕行数 / 评论数
  <BV号>.md       可读正文：简介 + 带时间轴字幕 + 高赞评论
```

> 为什么不在工作区里：Host 插件的 `process.cwd()` 是 profile 目录，不是会话工作区，
> 相对路径会指到 agent 读不到的地方。所以工具一律返回**绝对路径**。

## 四种取数方式

| 模式 | 行为 |
|---|---|
| `default` | 什么都不做，调用会被明确拒绝并说明原因 |
| `direct` | 本机直连 B 站官方 API |
| `self` | 直链与字幕走你自己的解析服务（把风控挪到服务器 IP） |
| `proxy` | 第三方解析站池 |
| `auto` | 探测自建服务器，不通就回落直连（**推荐**） |

在对话里说「把 B站学习器设成 auto 模式，并行度 6」，DSH 会写入 `~/.dsh-bili-learn/settings.json`。

## 必须知道的限制

**1. 字幕需要登录凭证。**

实测（2026-11-18）：无登录态时，`player/v2` 与签名版 `player/wbi/v2` 都返回 `code=0` 但字幕列表为空。这不是接口选错，是 B 站的行为。没有 `SESSDATA` 时，插件仍能拿到标题、简介和高赞评论，但正文要靠音频转写。

配置凭证：说「给 B站学习器配置 SESSDATA」，或直接编辑 `~/.dsh-bili-learn/settings.json`。

**2. 风控的计数单位是 IP，不是并发数。**

`concurrency` 只控制同时派多少个**子 agent 去读本地文件**。取数本身始终串行限速（默认 1.2 秒一次），因为实测同一 IP 连续约 30 次请求就开始返回 412。想提高总量，只能加出口 IP。

**3. 不使用 `view` 接口。**

`view` 是无 cookie 时最容易 -412 的端点。本插件改用 `search/type`（自带 `aid`）加 `player/pagelist`（自带 `cid`），全程避开它。

**4. 第三方站模式目前是占位。**

实测这批站点只返回视频/图片直链，不返回字幕与评论；主力站点响应 12 秒以上超时。所以 `proxy` 模式会说明情况并回落直连。
